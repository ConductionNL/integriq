## Coverage

- **Exhaustive:** all 9 orphan-scan findings under `lib/Service/**` triaged to a verdict with a superseded-check each; handler-resolution gate; the full auth/rate-limit/redaction path (`AuthorizationService`, `AuthenticationService`, `EndpointService::processAuthenticationRule`, `RateLimit/`); `domains`/`ips` traced repo-wide; every `@spec`→`changes/` anchor existence-checked.

Specs with no orphan-scan or security signal (e.g. `mapping-editor-ui`, `rule-editor-ui`, `sync-editor-ui`, `app-shell-and-logs-ui`) are **unverified** — UI specs need a browser pass this audit did not do.
- **Out of scope / UNSURE:** anything whose implementation moved into OpenRegister (export/import REQ-001…005). Verdicts there are about *this repo*; the OR side needs its own check.

## Bottom line

Of **26 `done`** specs: **1 is stale-by-supersession** (`configuration-export-import` — 5 REQs whose code now lives in OR; residue should be deleted, and REQ-005 redaction is unverified), **3 carry confirmed orphaned capabilities** (`endpoint-runtime` cache invalidation, `mapping-and-search` ×5 dead builders, `ibabs-notubiz-connector` write-back), and **1 phantom class** (`SlugTranslatorService`). Separately — and outside the `done` set but the highest-blast-radius finding here — **two live gateway security gaps** sit in `consumer-management` (status `implemented`): `domains`/`ips` are **advertised but unenforced**, and inbound rate limiting **only applies to JWT consumers**. The remaining ~21 `done` specs showed no defect signal but were **not exhaustively verified**.
